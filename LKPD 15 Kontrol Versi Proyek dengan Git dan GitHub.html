2 Ringkasan Teori: Kontrol Versi Proyek dengan Git dan GitHub

Bab 15: Git & GitHub

Version Control System (VCS) seperti Git memungkinkan pengembang melacak setiap revisi kode secara terstruktur, mengembalikan versi terdahulu jika terjadi kesalahan, serta bekerja pada cabang terisolasi (branching). Platform terpusat seperti GitHub melengkapi alur kerja ini dengan menyediakan repositori cloud, fitur integrasi tim, peninjauan kode melalui Pull Request (PR), serta penyelarasan berkas lewat perintah push dan pull.

Perintah Dasar Git (Local Workflow)

Proses pelacakan kode lokal melalui 3 area: Working Directory, Staging Area, dan Commit History.

git init
git add index.html
git commit -m "feat: tambah struktur HTML"

Percabangan (Branching) Kode

Membuat jalur pengembangan terisolasi agar fitur baru dapat diuji tanpa mengganggu kode utama (main).

git branch feature-x
git checkout feature-x
git merge feature-x

Remote Repository di GitHub

Menghubungkan repositori lokal ke server GitHub untuk mengunggah dan mengunduh pembaruan berkas.

git remote add origin https://github.com/user/repo.git
git push -u origin main
git pull origin main

Kolaborasi Tim & Pull Request (PR)

Mekanisme penggabungan kode tim di GitHub yang dilengkapi tinjauan kode (code review) sebelum disatukan ke branch utama.

1. Push branch feature ke GitHub
2. Open Pull Request (PR) di web GitHub
3. Review & Merge Pull Request
